# Sprint 2 Retro

## What went well
- Delivered a full vertical slice from landing through onboarding, filtering, listing, and comparison with no major blockers.
- Homepage clearly communicated the value prop with strong hierarchy, trusted university logos, and credibility metrics.
- Multi-step onboarding performed reliably (member type, age slider, city search, user details).
- Filtering, listing, and comparison produced accurate matches and clear plan cards for quick evaluation.

## What did not go well
- Delivered 47 of 55 planned points; some refinements remain.
- Stretch items (extra filters, backend improvements, micro-interactions) were deprioritized to ship the core flow.
- Plan listing and comparison UI still need spacing, mobile responsiveness, and design polish.
- Reliance on a static dataset limited filtering accuracy and scalability; dynamic data is needed.

## What we learned
- Stories sized at 3-5 points were the most predictable for planning.
- Building the full vertical slice early improved validation, alignment, and debugging speed.
- Establishing UI/UX guidelines earlier would have reduced spacing/typography/layout inconsistencies.
- Filtering workflow complexity calls for a modular approach to data processing and rendering.

## Action items and Sprint 3 preview
- Complete the user details flow with required field validation and a clear View Plans CTA.
- Deliver a plans listing page that surfaces total plans, insurers, and key highlights for quick evaluation.
- Expose optional add-ons via badges and expandable sections so users can personalize coverage.
- Add a clean Select Plan button with persistent selection state to support comparison and purchase flows.
- Move toward dynamic plan data to replace static datasets and improve filtering accuracy.
